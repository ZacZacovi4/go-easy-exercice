# Changelog

Toutes les __évolutions notables du projet__ doivent être consignées dans ce document en suivant ces consignes (cf. <https://keepachangelog.com/fr/>) :

- Conservez une section `Unreleased` en haut du fichier afin de lister tous les changements qui n'ont pas encore été publiés.
- Créer une nouvelle section dans le fichier `CHANGELOG.md` pour chaque version du projet. La version la plus récente se situe en haut du fichier.
- La date et l'auteur de chaque version doivent être indiqués.
- Regrouper les évolutions par type, dans cet ordre :
  - `Added` pour les nouvelles fonctionnalités.
  - `Changed` pour les modifications effectuées sur les fonctionnalités préexistantes.
  - `Deprecated` pour les fonctionnalités prochainement supprimées.
  - `Removed` pour les fonctionnalités supprimées.
  - `Fixed` pour les corrections de bugs et de vulnérabilités.
  - `Security` pour les vulnérabilités détectées.
